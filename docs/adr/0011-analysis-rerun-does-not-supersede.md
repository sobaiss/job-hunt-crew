# Analysis re-run creates an unlinked Analysis, not a supersede

Adding "Relancer l'analyse" to the Analyses-list Quick view meant deciding how a re-run should relate to the Analysis it's re-run from. Every other replace/regenerate flow in this codebase (CVVersion replace, GeneratedDocument regenerate) creates a new row and sets a `supersededById` link back to the old one, hiding the old row by default. We deliberately did not follow that pattern here: a re-run just calls the existing `POST /v1/analyses` — the same call both the Analysis detail page's existing FAILED-only "Relancer l'analyse" retry and `/analyses/new`'s "already analysed" shortcut already make — to create a brand-new, unrelated Analysis. No schema change, no link back, and the earlier Analysis (however it ended) stays listed in its own right. We chose this over adding `Analysis.supersededById` because it reuses an already-established, already-shipped code path instead of introducing a new one, at the cost of the two Analyses being indistinguishable as "the same attempt" beyond their date/status.
