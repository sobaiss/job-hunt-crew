# CV Conversion redacts candidate PII from the Markdown rendition

Every CVVersion's Markdown rendition (`markdownContent`) — the sole input to matching, the candidate's own read-only preview, and cover-letter/tailored-CV generation — used to faithfully reproduce whatever the uploaded file contained, including the candidate's name, email, phone, and other identifying data (docs/adr/0001). For confidentiality, Conversion now strips that identity data before saving `markdownContent`, via a new step: **Redaction** (see [services/analysis/CONTEXT.md](../../services/analysis/CONTEXT.md)).

Redaction removes the candidate's full name, email, phone, postal address, date of birth/age, nationality, marital status, gender, and any third-party reference's contact details, while deliberately keeping city/country of residence, employer/school names, job titles, dates, skills, certifications, languages, project descriptions, and URLs — all still useful for matching. It runs on every upload format: folded into the existing LLM normalisation pass for PDF/DOCX, and as a new minimal-diff-only LLM pass for Markdown/plain-text uploads that otherwise get no LLM call at all, preserving ADR 0001's no-unnecessary-rewrite guarantee for those formats. A deterministic regex/exact-match check for email, phone, and the account's own `User.name`/`User.email` follows as a safety net. Redaction only touches the stored Markdown rendition — the originally uploaded file in S3 is untouched.

Why: sending a candidate's name, email, and phone number into the matching/generation LLM pipeline serves no matching purpose (PRD.md's PII/GDPR open risk already flagged this class of exposure) and needlessly widens what a third-party LLM provider sees per Analysis. Folding it into Conversion, rather than a separate pass over already-stored data, means every reader of `markdownContent` — matching, preview, generation — sees the same redacted content by construction, with no unredacted copy ever existing elsewhere in the pipeline.

## Consequences

- Redaction failure (an LLM error after retries, or a safety-net hit) fails Conversion outright, the same as any other conversion failure — no unredacted fallback, no independent status field like `styleStatus`. Availability is traded for the guarantee that a failed Redaction can never silently leak PII into `markdownContent`.
- `CoverLetterWriterAgent`/`CvTailoringAgent` (docs/adr/0003) are bound to reproduce only what the base CVVersion's Markdown states, which no longer includes identity data. The generation pipeline now injects `User.name`/`User.email` into `GeneratedDocument.markdownContent` programmatically, outside the LLM call, so generated documents still carry a usable signature/contact block.
- Rollout is forward-only, matching how StyleProfile's own rollout worked (docs/adr/0008): existing CVVersions keep their unredacted `markdownContent` until the candidate manually re-triggers "Convert to Markdown."
- Removed spans are cleanly omitted, not replaced with a `[REDACTED]` placeholder; the candidate's read-only preview carries a small inline note explaining identity data was removed, since the rendition otherwise visibly differs from their upload with no explanation.
